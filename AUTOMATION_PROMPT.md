## Формат content — ТОЛЬКО Markdown (критично)
Редактор KIT хранит Markdown. Через API:
- Пиши Markdown: `##` заголовки, `**жирный**`, `_курсив_`, списки `*`, ссылки `[текст](url)`
- ЗАПРЕЩЕНО: любой HTML (`<p>`, `<h2>`, `<strong>`, `<ul>`, `<a>` и т.д.) — иначе в кабинете KIT поле «Содержание» пустое
- Абзацы разделяй пустой строкой

Пример фрагмента (как эталон уже сохранённой статьи):
```
Купили комплект — а после стирки он полинял… **постельное белье** выбирали на глаз…

## Кому какая ткань подходит

Не заучивайте названия — примерьте ткань под свой ритм.

*   **Сатин.** Гладкий хлопок…
*   **Жатка.** Почти не требует глажки…

_Жарко спите_ — хлопок. _Не гладите_ — жатка.

В подборке ниже — [комплекты постельного белья](https://kit39918.yastore.yandex.ru/catalog/postelnoe-bele).
```

## Стиль и структура (обязательно, для людей + SEO)
Не сухой SEO-текст. Тон: тёплый магазин домашнего текстиля, на «вы», без канцелярита.
Ключ из колонки C — естественно в title/seo и 2–4 раза в тексте, без набивки.

Каждая статья строго по структуре:
1) Живой заход (сцена/проблема) — 1–2 абзаца
2) Мини-история / типичная ошибка покупателя — 1 абзац
3) Кому что подходит (сценарии выбора) — с `##` и списками `*`
4) Конкретика + чек-лист перед покупкой — список
5) Практический блок по теме (размеры/уход/сравнение — по смыслу ключа)
6) FAQ — 3–4 коротких Q&A (`**Вопрос?**` + ответ)
7) Мягкий CTA к полке товаров + markdown-ссылка на релевантную категорию/каталог магазина, если URL известен из API

Эталон по смыслу: уже опубликованный пост про постельное бельё (slug postelnoe-bele-kak-vybrat-kachestvennyy-komplekt).

## Публикация (API https://api.kit.yandex.net)
Для каждой из 5 тем:
1. Написать статью по структуре и в Markdown
2. Заполнить: title, short_description, slug (латиница/дефисы), seo_title, seo_h1, seo_description, tags, blog_dates.start_date (сейчас), status=ACTIVE
3. preview_media, desktop_media, mobile_media — одно IMAGE с image_id
4. attachment: CATEGORY или COLLECTION с релевантными товарами
5. POST /v1/blogs
6. Публичный URL: `{b2c_url из GET /v1/store}/blog/{slug}` (уточни актуальный путь блога магазина при необходимости)
